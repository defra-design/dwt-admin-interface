User story

As a member of Defra staff who uses the DWT admin portal,
I want to change the name of a client after it has been created,
so that I can correct a mistake in the name, or update it when the software provider’s product changes name, without creating new credentials.

Context

This story changes the software provider page built in DWTSPI-496. The client name is entered once, when the credentials are created in DWTA-458, and cannot be changed afterwards.

Changing the name changes only the name. The client ID and the secrets stay the same, so the software provider does not need to change anything. The edit page is the create page with the current name filled in, so the rules for a valid name are the ones already built.

Acceptance criteria

Software provider page

  1. Beside the H1 is a link, “Edit”, on the same line as the client name, after it. The text of the link and the H1 line up on their baseline.
  2. The gap between the H1 and the link is 20px, which is spacing unit 4. The gap between the heading and the tag below it is still spacing unit 4 (20px).
  3. Given the client name is long, or the screen is narrow, then the link wraps below the H1.
  4. Given I select “Edit”, then I go to the edit client name page for that client.

Edit client name page

  1. The page title is “Edit client name - DWT admin portal”. When there is an error it starts with “Error: ”.
  2. There is no caption above the H1. The H1 is “Edit client name”.
  3. There is one text input, with the label “Client name” in the small bold label style, and the current client name filled in.
  4. The hint is “Enter the name of the software provider and software package, using letters and underscores only. For example, Waste_Technologies_Software”, with no full stop at the end.
  5. Below the input is a button, “Save”, with a link, “Cancel”, beside it. “Cancel” goes to the software provider page for that client without saving.

Saving

  1. Given I enter a valid name and select “Save”, then the name is changed and I go to the software provider page. The H1, the page title and the row in the Software providers table show the new name.
  2. Given I select “Save” without changing the name, then I go to the software provider page and nothing changes.
  3. Changing the name does not change the client ID, the secrets, or the date and time each secret was generated.
  4. Given the name is not valid, then the page shows the error summary and field error built in DWTA-458, and keeps what I entered. The client’s own current name is not treated as “already exists”.

On every page in this ticket

  1. Everything else on these pages works as before.
  2. The pages match the design references.

Accessibility acceptance criteria

On every page in this ticket, meets WCAG 2.2 AA:

  1. The “Edit” link has visually hidden text after it, “ client name”, so its accessible name is “Edit client name” and it makes sense out of context (2.4.4).
  2. The H1 and the link are separate elements. The link is not inside the H1, so the H1 is still only the client name (1.3.1, 2.4.6).
  3. The link is after the H1 in the page, so the reading order and the tab order match what people see, including when the link wraps below the heading (1.3.2, 2.4.3).
  4. The input has a visible label, linked to it with for and id. The hint is linked with aria-describedby. The input has autocomplete="off", because the name is not about the person (1.3.1, 3.3.2).
  5. Given there is an error, then an error summary is at the top of the page, focus moves to it, and each error links to the input. The field error is linked with aria-describedby (3.3.1, 4.1.3).
  6. Given I have a name in the input and save with an error, then the input still holds what I entered, so I do not have to enter it again (3.3.7).
  7. The edit page has one H1. The page title is unique and matches the H1 (1.3.1, 2.4.2).
  8. Every link and button can be used with a keyboard, in an order that matches the page. The focus state is the GOV.UK focus style, with the focus colour (#ffdd00) as the background and focus-text (#0b0c0c) as the text (2.1.1, 2.4.3, 2.4.7).
  9. The pages have no horizontal scrolling at 320px wide or at 200% zoom. A long client name wraps in the H1 and in the input (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE, on both pages, and on the edit page with an error.
  • With only a keyboard, go from the software provider page to the edit page, change the name and save.
  • Check the link, the input and the error with a screen reader, such as NVDA or VoiceOver. Check that the link is read as “Edit client name”.
  • Check both pages at 320px wide and at 200% zoom, with a long client name.
  • Turn off JavaScript. Check that editing and saving still work.

Out of scope

  • Changing the environment, the client ID or the secrets.
  • A message to confirm the name was changed.
  • Telling the software provider about the new name.
  • A message if saving fails. See DWTSPI-493.
  • The characters allowed in a client name. See Allowed characters in the client name.
