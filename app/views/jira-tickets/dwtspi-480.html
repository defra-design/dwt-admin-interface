Find waste organisations by registration date

Design reference

{{ govukButton({ text: "View the design reference page (results)", href: "/jira-tickets/dwtspi-480/design", classes: "govuk-button--secondary" }) }} {{ govukButton({ text: "View the design reference page (errors)", href: "/jira-tickets/dwtspi-480/design-error", classes: "govuk-button--secondary" }) }}

User story

As a member of Defra staff who uses the DWT admin portal,
I want to search by registration date and get a clear message if a date is wrong,
so that I only see the organisations I asked for, and know how to fix a mistake.

Context

This story changes the Waste organisations page. Nothing shows until someone searches by a From and To registration date. The error messages follow the GOV.UK dates pattern, with the wording below.

The table has a new column order and shows the full organisation ID under the name. Every page in the service is wider, and the table text is smaller, so more fits on screen and the column headings stay on one line.

Acceptance criteria

The page

  1. The page title is “Waste organisations - DWT admin portal”, and the H1 is “Waste organisations”.
  2. On every page of the service, the page container is 1100px wide, including the header, navigation and footer.
  3. Under the H1 is a group with the H2 “Registration date”. In it are two date inputs, side by side: “From date” with the hint “For example, 1 4 2025”, then “To date” with the hint “For example, 31 3 2026”. Each has Day, Month and Year fields.
  4. Below the group are a primary button, “Search”, and a link, “Clear”, side by side. Given I select “Clear”, then I see the page as it first loads.
  5. Given the page loads for the first time, or I have selected “Clear”, then the date fields are empty and no results are shown.

The results

  1. Given I enter a valid From date and To date and select “Search”, then the results are shown below the filter. Dates before 20 June 2026 are allowed. The From date can be the same as the To date.
  2. The gap between the filter and the results heading is spacing unit 9 (60px). The heading is an H2: “Waste organisations registered from [From date] to [To date]”, for example “Waste organisations registered from 1 January 2026 to 1 October 2026”.
  3. Below the H2 is the line “Organisations registered in period: [number] of [total] total”, where [total] is every registered organisation. When there are results, the link “download CSV” is on the same line.
  4. The table has five columns, in this order: Organisation name and ID, Active API codes, Registered, Payment year ending, Payment status.
  5. The first column shows the organisation name in bold, and the full organisation ID below it on its own line. The ID is in type scale point 16 and the secondary text colour. When the name is not known, the name is “(Not known)”, and the ID is still shown.
  6. Registered shows the date as, for example, “1 Jan 2026”. Payment year ending shows the month and year the payment year ends, for example “Sep 2027”, and is empty when there is no payment year. Payment status shows a green “Paid” tag, a blue “In progress” tag or a red “Unpaid” tag.
  7. The table text, the column headings and the tags are in type scale point 16 (1rem, with a 20px line height). The column headings stay on one line at a page width of 1100px.
  8. The table loads sorted by Registered, with the oldest first. Every column can be sorted. All rows are on one page, with no pagination, so sorting reorders every row.
  9. Given no organisations registered in the period, then no table and no download link are shown. The page says “No organisations were registered in this period. Try a different date range, or select Clear.”.

Errors

  1. Given a date is wrong, when I select “Search”, then no results are shown, and the dates I entered are kept.
  2. An error summary with the title “There is a problem” is above the H1. It has one link for each error, in the order From then To. Each link goes to the first wrong input. The page title starts with “Error: ”.
  3. The group has a red line down its left, from the H2 down. The error messages are between the H2 and the date inputs, one for each date that is wrong. Only the Day, Month or Year inputs that are wrong have a red border.
  4. One message is shown for each date: the first in the table below that applies. The “To before From” error is only shown when the To date has no other error.

Accessibility acceptance criteria

On the Waste organisations page, meets WCAG 2.2 AA:

  1. The page has one H1. “Registration date” is an H2 inside the legend of the group, and the results heading is an H2 (1.3.1, 2.4.6).
  2. The page title is unique, with the page name then “DWT admin portal”. On an error page it starts with “Error: ” (2.4.2).
  3. The error summary is above the H1, and focus moves to it when the page loads with errors. Each link goes to the first wrong input (3.3.1, 2.4.3).
  4. The group is a fieldset with the legend “Registration date”. Each date input is a nested fieldset with the legend “From date” or “To date”. The group has aria-describedby pointing to its error messages. Each message starts with the visually hidden text “Error:” (1.3.1, 3.3.1, 4.1.2).
  5. Errors are not shown by colour alone. Each has the message text, a red line down the left of the group and a red border on the wrong inputs (1.4.1). Error red on white is about 5.2:1 (1.4.3, 1.4.11).
  6. The table has header cells with scope="col", and the organisation name is a row header with scope="row". The table is named by the results heading with aria-labelledby. Each sortable heading is a button, and aria-sort shows the sort order (1.3.1, 4.1.2).
  7. The sort icons are decorative (aria-hidden="true") and are 22px wide when a heading wraps (1.1.1).
  8. The link “Clear” has the accessible name “Clear search”, which starts with its visible label (2.5.3).
  9. Every function works with a keyboard, in an order that matches the page. The focus state is the GOV.UK focus style, with the focus colour (#ffdd00) as the background and focus-text (#0b0c0c) as the text (2.1.1, 2.4.3, 2.4.7).
  10. The status tags show the status in words, so the colour is not the only way to tell them apart (1.4.1). Tag text on its background is about 9:1 (1.4.3).
  11. The page has no horizontal scrolling at 320px wide or at 200% zoom, except inside the data table (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE, on the results page and the error page.
  • Try every row of the error messages table, and check the wording and the red borders.
  • Use only a keyboard to search, sort a column and select “Clear”.
  • Check the error summary, the group, the table and the sort order with a screen reader, such as NVDA or VoiceOver.
  • Check the page at 320px wide and at 200% zoom.
  • Turn off JavaScript. Check that the table still shows and the search still works.

Out of scope

  • Redesigning the filter. It will change in the next iteration.
  • Text above the filter about organisations registered before 20 June 2026. It is not in this design.
