User story

As a member of Defra staff who uses the DWT admin portal,
I want to be told when the service could not create or change credentials,
so that I know nothing has changed and I can try again, instead of thinking the action worked.

Context

Creating credentials, adding, replacing or removing a secret, deleting a software provider and changing a client name all change data. Today the pages only handle a person entering an invalid name. If the service itself fails, there is nothing to say so.

The alert goes on the page the person can try the action from again. Replace, remove and delete are confirmed on a page that is only a card, so after a failure the person goes back to the software provider page, where the alert is shown.

Build this after DWTSPI-469 and DWTSPI-502, because the delete and edit errors need those journeys.

Acceptance criteria

The alert

The heading is the same each time, and the text depends on what failed:

  1. The alert is a MoJ alert in the error variant. Its heading is an H2 and it has no dismiss button.
  2. The alert is the first content in the main part of the page, above the caption and the H1. The gap between the alert and the next content is spacing unit 7 (40px).
  3. The page title is the same as when there is no alert.

When it is shown

  1. Given I select “Generate credentials” and the credentials cannot be created, then the create credentials page is shown again with the alert, the name I entered is still in the input, and no credentials exist.
  2. Given I select “Save” and the name cannot be changed, then the edit client name page is shown again with the alert, the name I entered is still in the input, and the client keeps its old name.
  3. Given I select “Yes, replace secret”, “Yes, remove secret” or “Yes, delete software provider” and it fails, then I go to the software provider page with the alert, and the secret or the client is as it was.
  4. Given I select “Add another secret” and it fails, then the software provider page is shown again with the alert and no secret is added.
  5. Given I try again and it works, then the journey carries on as built, and the alert is not shown.
  6. The alert is not shown for a name that is not valid. That still shows the error summary and field error built in DWTA-458.
  7. The pages match the design references.

Accessibility acceptance criteria

On every page that can show the alert, meets WCAG 2.2 AA:

  1. The alert has role="alert", so a screen reader reads it when the page loads. The accessible name is “error: Sorry, there is a problem with the service” (4.1.3).
  2. Focus moves to the alert when the page loads, and the focus state is the GOV.UK focus style, with the focus colour (#ffdd00). The alert does not have disableAutoFocus (2.4.3, 2.4.7).
  3. The icon is decorative (role="presentation" and focusable="false"). The error is given in words, not by the icon or colour alone (1.1.1, 1.4.1).
  4. The alert heading is an H2, which comes before the H1 in the page, in the same way as the error summary. There is one H1 (1.3.1, 2.4.6).
  5. The alert text is black on white, about 19:1. The border and icon are red on white, about 5.2:1 (1.4.3, 1.4.11).
  6. When the page is shown again, what I entered is still in the input, so I do not have to enter it again (3.3.7).
  7. Every link and button can be used with a keyboard, in an order that matches the page. The alert has no dismiss button to tab to (2.1.1, 2.4.3).
  8. The pages have no horizontal scrolling at 320px wide or at 200% zoom. A long client name wraps in the alert text and the page (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE, on each page with the alert.
  • With only a keyboard, cause each failure, and check that focus lands on the alert and that the next Tab goes to the first control after it.
  • Check the alert with a screen reader, such as NVDA or VoiceOver. Check that it is read when the page loads, and that the name and text are read.
  • Check each page at 320px wide and at 200% zoom.
  • Turn off JavaScript. Check that the alert is still shown first in the page and the action can be tried again.

Out of scope

  • What causes the failure, and what the service does to recover.
  • A link to contact the team, or a reference number for the failure.
  • Errors on other pages, such as loading the Software providers page or the Waste organisations report.
  • The error summary for a name that is not valid. See DWTA-458.
  • A success message after adding, replacing or removing a secret, or changing the client name.
