Allowed characters in the client name

Clickable prototype: No prototype version shows this yet.

The design and acceptance criteria for this change, to use when a ticket is written for it. It has no ticket number yet. It changes the name page built in DWTA-458, which only allows letters and underscores, so that the client name can also include numbers, hyphens and full stops.

The allowed characters are A to Z, a to z, 0 to 9, _ (underscore), - (hyphen) and . (full stop). Spaces are not allowed. This needs confirming with the developers.

Acceptance criteria

On the name page:

  1. Between the H1 and the input is a paragraph: “You can use letters, numbers, underscores (_), hyphens (-) and full stops (.). Do not use spaces.”. The rules are in the page, not hidden in a details component, so I can read them before I type.
  2. The hint is “Enter the name of the software provider and software package, for example, Waste_Technologies_Software.”.
  3. Spellcheck is off on the input (spellcheck="false").
  4. Given the client name has anything in it other than the characters listed in the paragraph above the input, including a space, then the error is “Client name must only include letters, numbers, underscores, hyphens and full stops”. See the invalid characters error design. What I typed is not changed, and no characters are removed.
  5. The characters are checked on the server, when I select “Generate credentials”. The input has no pattern attribute, because browsers show their own error messages, which we cannot word or make accessible. The form keeps novalidate so that only our error summary and error message show.
  6. Given the client name only has the allowed characters in it, then it passes this check. The empty name and duplicate name errors are unchanged.
  7. The pages match the design references.

Accessibility acceptance criteria

On the name page, meets WCAG 2.2 AA:

  1. The paragraph above the input is real text. A screen reader reads it before the label and input, so the rules are heard before the user types. The symbols are named in words (underscores, hyphens, full stops), with the symbol in brackets (1.3.1, 3.3.2).
  2. The error message is the same in the error summary and beside the input, and says what the user can use (3.3.1, 3.3.3).
  3. Spellcheck is off, so the browser does not underline names such as “Waste_Technologies_Software” as spelling mistakes.

How to test

  • Enter a name with a space, then names with each allowed character. Check that only the name with the space shows the error.
  • Check the paragraph and the error with a screen reader, such as NVDA or VoiceOver.
  • Check the page at 320px wide and at 200% zoom.

Out of scope

  • A limit on the length of the client name. There is no limit yet.
  • Changing the name of a client after it has been created.
