User story

As a member of Defra staff who uses the DWT admin portal,
I want to delete a software provider, including all of its credentials,
so that the portal does not hold a record for a software provider we no longer work with.

Context

This story changes the software provider page built in DWTSPI-496 and the Software providers page built in DWTA-456. Today there is no way to remove a software provider once it has been created.

Deleting removes the whole record for the client, including its secrets, and cannot be undone. So the link goes to a confirmation page first, in the same way as replacing or removing a secret in DWTA-466. After the deletion the person returns to the list, which shows an alert, because the only other sign that it worked is a missing row.

Acceptance criteria

Software provider page

  1. At the bottom of the page is a link, “Delete software provider”. It is below the secrets table and, when it is shown, the “Add another secret” button.
  2. The gap between the table or button above and the link is spacing unit 9 (60px).
  3. Given I select “Delete software provider”, then I go to the confirmation page for that client.

Confirmation page

  1. The page title is “Are you sure you want to delete the software provider? - DWT admin portal”.
  2. The page has an interruption card as its only content. Its H1 is “Are you sure you want to delete the software provider?”.
  3. The text in the card is “You will delete the entire record for [client name] including all the credentials.”, with the name of the client I came from, for example “Kerbside_Collect_Test”.
  4. The card has a button, “Yes, delete software provider”, and a link, “Go back to software provider”, side by side. The link goes to the software provider page for that client. Nothing is deleted.
  5. Given I select “Yes, delete software provider”, then the client and all of its secrets are deleted, and I go to the Software providers page.

Software providers page after deleting

  1. Above the H1 is a success alert. Its heading is “Software provider deleted” and its text is “[client name] has been deleted.”, with the name of the client I deleted, and a full stop at the end. The alert cannot be dismissed.
  2. The gap between the alert and the H1 is spacing unit 7 (40px).
  3. The deleted client is not in the table.
  4. The alert is only shown straight after a deletion. Given I reload the page, or come back to it later, then the alert is not shown.
  5. Given the client has been deleted, then going to its software provider page or its confirmation page takes me to the Software providers page.

On every page in this ticket

  1. Everything else on these pages works as before.
  2. The pages match the design references.

Accessibility acceptance criteria

On every page in this ticket, meets WCAG 2.2 AA:

  1. “Delete software provider” is a link, because it goes to another page. “Yes, delete software provider” is a button in a form, because it changes data (4.1.2).
  2. Deleting needs a second step, the confirmation page, so a mistaken selection can be undone before any data is deleted (3.3.4).
  3. The confirmation page has one H1, which is the card heading. Its page title is unique and matches the H1 (1.3.1, 2.4.2, 2.4.6).
  4. On the Software providers page the alert heading is an H2, which comes before the H1 in the page. The alert has role="region" and the accessible name “success: Software provider deleted”. Its icon is decorative (role="presentation" and focusable="false"). Success is given in words, not by the icon or colour alone (1.1.1, 1.3.1, 1.4.1).
  5. Focus is not moved to the success alert when the page loads. It is the first content after the navigation, so a screen reader reads it before the H1 (2.4.3).
  6. Every link and button can be used with a keyboard, in an order that matches the page. The focus state is the GOV.UK focus style, with the focus colour (#ffdd00) as the background and focus-text (#0b0c0c) as the text. On the card, the link and button use the inverse style, and keep a visible focus state (2.1.1, 2.4.3, 2.4.7).
  7. The alert text is black on white, about 19:1. The border and icon are green on white, about 5.3:1 (1.4.3, 1.4.11).
  8. The pages have no horizontal scrolling at 320px wide or at 200% zoom. A long client name wraps in the card and in the alert (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE, on each page.
  • With only a keyboard, go from the software provider page to the confirmation page, delete the client, and check where focus goes.
  • Check the link, the card and the alert with a screen reader, such as NVDA or VoiceOver. Check that the alert is read, and that it names the client.
  • Check each page at 320px wide and at 200% zoom, with a long client name.
  • Turn off JavaScript. Check that the link, the confirmation and the alert still work.

Out of scope

  • Undoing a deletion, or a way to recover a deleted client.
  • What happens to software providers that are already using the deleted credentials, or telling them.
  • Deleting a single secret. See DWTA-466.
  • What the Software providers page shows when the last client is deleted.
  • A message if the deletion fails. See DWTSPI-493.
