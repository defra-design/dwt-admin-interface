Make it clear that new client credentials must be copied

Design reference

{{ govukButton({ text: "View the design reference page (External test)", href: "/jira-tickets/copy-credentials-page/design", classes: "govuk-button--secondary" }) }}

User need

As a member of Defra staff
I need to copy the credentials and understand why I must do so now
so that I can send them to the software provider.

User story

As a member of Defra staff who uses the DWT admin portal,
I want to know straight away that I must copy the new credentials, and to copy them all at once,
so that I do not leave the page without the secret.

Context

This story changes the “Copy the client credentials” page built in DWTA-458. The same page is shown after replacing a secret and after adding another secret (DWTA-466). Where the Close button goes, and the “New” tag shown after it, are in Manage a client’s secrets from its software provider page.

The built page has warning text, a heading, a panel and two buttons that compete for attention, and the “copied” message beside the Copy button pushes the Close button sideways. The new page has one message, the credentials in a plain list, and copying as the main action. The change to the button label follows the MoJ and GOV.UK Design System copy buttons.

The page only shows the one new set of credentials. After adding another secret, the existing secret is no longer shown below it, because the software provider page lists every secret. This page is only for copying.

The interaction designer compared the MoJ alert with GOV.UK warning text and chose the alert. The warning text version is kept in the prototype for the record: copy page with warning text.

The alert heading, “You must copy the credentials”, and its text, “You cannot view the client secret after closing this page.”, are from the content designer.

There is no research behind this design yet. We are building it so that we can learn from it, and we will test it in user research once it is built. One thing we most want to learn is whether one message is enough, or whether people miss it.

Contrast: black on white is about 19:1, which passes for text (4.5:1). $moj-warning-colour on white is about 3.4:1, which passes for the border and icon (3:1) but would not pass for text. No text uses it. Testers must confirm both.

Acceptance criteria

On the copy page. These replace DWTA-458 AC 13 to 19, and DWTA-466 AC 14 and 15:

  1. Above the H1 is a caption with the client name, for example “Kerbside_Collect_Test”. The H1 is still “Copy the client credentials”.
  2. Below the H1 is a warning alert, which replaces the warning text. Its heading is “You must copy the credentials” and its text is “You cannot view the client secret after closing this page.”. The alert cannot be dismissed.
  3. Below the alert is a summary list, which replaces the panel and the H2 with the client name. It shows, in this order: Client ID, Client secret, External test environment and Generated on. The client secret is shown in full. The value of External test environment is the API URL.
  4. The gap between the H1 and the alert is spacing unit 7 (40px). The gap between the alert and the summary list is spacing unit 9 (60px). The gap between the summary list and the buttons is spacing unit 4 (20px).
  5. The page only shows the new credentials. Given I have added another secret, then the existing secret is not shown on this page.
  6. Given JavaScript is on, then there is a primary button, “Copy credentials”, with a secondary button, “Close”, beside it. Given JavaScript is off, then only “Close” is shown. There is no back link.
  7. Given I select “Copy credentials”, then the client ID, client secret, environment with its API URL, and generated on date are copied as plain text, in the same order as the summary list. Each label is on its own line, followed by its value, with a blank line between each pair.
  8. Given I have copied the credentials, then the button label changes to “Credentials copied” for four seconds, then back to “Copy credentials”. No message appears beside the button, and the Close button does not move.
  9. Everything else built in DWTA-458 and DWTA-466 for this page works as before, including the page title, the date format, the environment and API URL, and not showing the secret again after I have left the page.
  10. The page matches the design reference.

Accessibility acceptance criteria

On the copy page, meets WCAG 2.2 AA:

  1. The page has one H1. The caption with the client name is a span, not a heading. The alert heading is an H2, so the headings are in order (1.3.1, 2.4.6).
  2. The alert has role="region" and the accessible name “warning: You must copy the credentials”, so screen reader users can find it. Its icon is decorative (role="presentation" and focusable="false"), and the warning is given in words, not by the icon or colour alone (1.1.1, 1.3.1, 1.4.1).
  3. Focus is not moved to the alert when the page loads. The alert comes straight after the H1, so a screen reader reads it next (2.4.3).
  4. The summary list is a dl, with each label in a dt and each value in a dd. The client ID and client secret are text that can be selected (1.3.1).
  5. The Copy button’s accessible name is “Copy credentials client ID and client secret”, which starts with its visible label (2.5.3).
  6. When the credentials are copied, a visually hidden role="status" region with aria-live="polite" announces “Client credentials copied”. Focus stays on the button while its label changes (4.1.3, 3.2.2).
  7. Every button can be used with a keyboard, in an order that matches the page. The focus state is the GOV.UK focus style, with the focus colour (#ffdd00) as the background and focus-text (#0b0c0c) as the text (2.1.1, 2.4.3, 2.4.7).
  8. The alert text is black on white, about 19:1. The border and icon are $moj-warning-colour on white, about 3.4:1 (1.4.3, 1.4.11).
  9. The page has no horizontal scrolling at 320px wide or at 200% zoom. The client secret and the API URL have no spaces, so testers must confirm they wrap inside the summary list (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE.
  • Create credentials, add a secret and replace a secret, using only a keyboard, and copy the credentials each time.
  • Check the alert, the summary list and the “copied” announcement with a screen reader, such as NVDA or VoiceOver.
  • Check the page at 320px wide and at 200% zoom.
  • Turn off JavaScript. Check that the Copy button is not shown, Close still works, and the credentials can be selected and copied by hand.

Out of scope

  • Where the Close button goes, and the “New” tag. These are in Manage a client’s secrets from its software provider page.
  • The name page. The change to the characters allowed in a client name is in Allowed characters in the client name.
  • The real API URL for each environment.
  • Showing a secret again after it has been created.
