DWTSPI-490

Tell users when we could not show a new secret

Clickable prototype: No prototype version shows this yet.

User story

As a member of Defra staff who uses the DWT admin portal,
I want to be told when a new secret was created but we could not show it to me,
so that I know what to do next and do not give the software provider a secret that does not exist or is not known.

Context

When a user creates credentials, replaces a secret or adds another secret, the secret is created first and then shown once. If the request times out, the secret can exist without us receiving it. The user cannot see it and cannot get it again.

The standard error page says “Your information has not been saved”. That is not true here, so these cases need their own message. The message tells the user what to do next.

Deleting a software provider needs no new message. If the request times out but the provider is deleted, the user can search the list of software providers to check.

Design acceptance criteria

New page content, based on the existing “Sorry, there is a problem with the service” page in version 9. The “Try again later” and “Your information has not been saved” text is not used.

  1. The page has the same layout as the existing problem with the service page.
  2. The H1 is “Sorry, there is a problem with the service”.
  3. Under the H1 is one paragraph with the message for the case, from the table below.
  4. The paragraph is body text, with the GOV.UK default spacing below the H1.
  5. The page matches the content in the table.

Open question

After a timed-out “Add another secret”, the software provider has two secrets and the user can only remove one. The message depends on which secret they can remove.

  • If they can remove either secret, we could say: “You need to remove the newest secret and add another secret. We could not show it to you.” The newest secret is the one with the latest generated date.
  • If they can only remove the oldest secret, that secret is probably the one the software provider is using. Removing it would stop their software working. Confirm with the team what the user should do before writing the message.

Acceptance criteria

  1. Given a user selects “Yes, replace secret”, when the request times out and the new secret was created but not received, then the user sees the Replace a secret message.
  2. Given a user creates new credentials, when the request times out and the credentials were created but the secret was not received, then the user sees the Create new credentials message, with the client name of the new credentials in place of [client name].
  3. Given a user adds another secret, when the request times out and the secret was created but not received, then the user sees the Add another secret message.
  4. Given a user sees one of these messages, when they want to carry on, then there is a link back to the software provider.
  5. Given a request times out and no secret was created, then the user sees the existing problem with the service page.

Accessibility acceptance criteria

Meets WCAG 2.2 AA:

  1. The page has one H1, “Sorry, there is a problem with the service” (1.3.1, 2.4.6).
  2. The page title is “Sorry, there is a problem with the service”, followed by the service name (2.4.2).
  3. The page has one banner, one labelled navigation, one main and one contentinfo landmark (1.3.1).
  4. The message is in the page text, so a screen reader reads it as soon as the page loads. The client name is in the text, not only in an image or a tooltip (1.3.1, 4.1.3).
  5. The link back to the software provider has text that makes sense out of context, and shows the GOV.UK focus style, with focus as the background and focus-text as the text (2.4.4, 2.4.7).
  6. A long client name wraps and does not make the page scroll sideways at 320px wide or at 200% zoom (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE.
  • With only a keyboard, tab to the link back to the software provider.
  • Check the page with a screen reader, such as NVDA or VoiceOver. The H1 and message are read.
  • Check the page at 320px wide and at 200% zoom, with a long client name.

Out of scope

  • Showing the lost secret to the user, or recovering it.
  • A new message for deleting a software provider.
  • Changing what happens when a request fails before anything is created.
  • Telling the software provider that their secret has changed.
