User story

As a member of Defra staff who uses the DWT admin portal,
I want to go from a client in the list to one page with its details and secrets, add, replace or remove a secret from there, and copy new credentials before I leave the page that shows them,
so that I can see when each secret was generated, change the right one, and send the credentials to the software provider.

Context

This story changes pages built in DWTA-456, DWTA-458 and DWTA-466. The Manage client credentials page is replaced by a software provider page, which you reach by selecting the client name in the table. Adding, replacing and removing a secret work as built. What changes is the page they start from and the page they return to.

The “Copy the client credentials” page, shown after creating credentials, adding a secret or replacing a secret, is redesigned in the same story. Its Close button goes to the software provider page, so the two pages are built together.

Replacing or removing a secret now goes through an interstitial, which asks the person to confirm the destructive action before it happens.

Both the tag and the H2 name the environment. There are five environments, and people only see the credentials for the environment they are in. The “New” tag shows which secret has just been created, after the copy page is closed.

Acceptance criteria

Software providers page

These replace DWTA-466 AC 1 to 3:

  1. The table has three columns, in this order: Client name, Client ID, Environment. There is no Client secret column.
  2. In each row, the client name is a link to the software provider page for that client.

Software provider page

This page replaces the Manage client credentials page. These replace DWTA-466 AC 4 to 13:

  1. The page title is the client name followed by “ - DWT admin portal”, for example “Kerbside_Collect_Test - DWT admin portal”.
  2. At the top of the page is a back link, “Back”, which goes to the Software providers page.
  3. Above the H1 is a caption, “Software provider”. The H1 is the client name.
  4. Below the H1 is a tag in the default style with the name of the environment the user is in, for example “External test”. The gap between the H1 and the tag is spacing unit 4 (20px).
  5. Below the tag is a summary list with no borders and one row: “Client ID” and the client ID.
  6. Below the summary list is an H2, “Client secrets for [environment] environment”, for example “Client secrets for external test environment”. The gaps between the tag and the summary list, and between the summary list and the H2, are spacing unit 8 (50px).
  7. Below the H2 is a table of the client’s secrets, newest first, with the columns Generated on, Client secret and Actions. The gap between the H2 and the table is spacing unit 4 (20px).
  8. Generated on is the date and time the secret was created, for example “21 October 2026 at 8:14am”. Every client secret is shown as “[Hidden]”.
  9. Given the client has one secret, then its Actions cell has a link, “Replace secret”, and below the table is a secondary button, “Add another secret”.
  10. Given the client has two secrets, then the older secret’s Actions cell has a link, “Remove secret”, the newest secret’s Actions cell is empty, and “Add another secret” is not shown.
  11. Given I select “Add another secret”, then a new secret is created straight away, with no confirmation, and I go to the copy credentials page showing the new secret. The existing secret keeps working.
  12. Given I select “Replace secret” or “Remove secret”, then I go to the replace or remove interstitial.

Copy credentials page

Shown after creating credentials, adding a secret or replacing a secret. These replace DWTA-458 AC 13 to 19, and DWTA-466 AC 14 and 15:

  1. Above the H1 is a caption with the client name, for example “Kerbside_Collect_Test”. The H1 is “Copy the client credentials”.
  2. Below the H1 is a warning alert, which replaces the warning text. Its heading is “You must copy the credentials” and its text is “You cannot view the client secret after closing this page.”. The alert cannot be dismissed.
  3. Below the alert is a summary list, which replaces the panel and the H2 with the client name. It shows, in this order: Client ID, Client secret, External test environment and Generated on. The client secret is shown in full. The value of External test environment is the API URL.
  4. The gap between the H1 and the alert is spacing unit 7 (40px). The gap between the alert and the summary list is spacing unit 9 (60px). The gap between the summary list and the buttons is spacing unit 4 (20px).
  5. The page only shows the new credentials. Given I have added another secret, then the existing secret is not shown on this page.
  6. Given JavaScript is on, then there is a primary button, “Copy credentials”, with a secondary button, “Close”, beside it. Given JavaScript is off, then only “Close” is shown. There is no back link.
  7. Given I select “Copy credentials”, then the client ID, client secret, environment with its API URL, and generated on date are copied as plain text, in the same order as the summary list. Each label is on its own line, followed by its value, with a blank line between each pair.
  8. Given I have copied the credentials, then the button label changes to “Credentials copied” for four seconds, then back to “Copy credentials”. No message appears beside the button, and the Close button does not move.

After the copy credentials page

These replace DWTA-458 AC 20 and 21, and DWTA-466 AC 16:

  1. Given I select “Close” on the copy credentials page, then I go to the software provider page for that client.
  2. Given I have just closed the copy credentials page, then the newest secret has a green “New” tag after its Generated on date. See the design with two secrets.
  3. Given I reload the software provider page, or come back to it later, then the “New” tag is not shown.
  4. Given I have left the copy credentials page and go back to it, then the secret is not shown and I go to the software provider page.

Replace and remove interstitials

These replace the link in DWTA-466 AC 20 and 26, and where I go in AC 27:

  1. The link on the card is “Go back to software provider”. It goes to the software provider page.
  2. Given I select “Yes, remove secret”, then the older secret is removed and I go to the software provider page, which shows one secret.

On every page in this ticket

  1. The environment is the one the user is in. In the tag it is capitalised, for example “External test”. In the H2 it is in lower case, for example “external test”. The design reference shows External test.
  2. Everything else built in DWTA-456, DWTA-458 and DWTA-466 works as before, including the page titles, the date format, the environment and API URL, and not showing the secret again after I have left the copy credentials page.
  3. The pages match the design references.

Accessibility acceptance criteria

On every page in this ticket, meets WCAG 2.2 AA:

  1. Each client name link in the table has the client name as its text, so every link has a different name that says where it goes (2.4.4).
  2. Each page has one H1. The caption above it is a span, not a heading. On the software provider page the H2 “Client secrets for [environment] environment” comes next. On the copy credentials page the alert heading is an H2. So the headings are in order (1.3.1, 2.4.6).
  3. The page title is unique. The software provider page title starts with the client name (2.4.2).
  4. The secrets table has a visually hidden caption, “Client secrets for [environment] environment”, and its column headings are th elements with scope="col" (1.3.1).
  5. Each “Replace secret” and “Remove secret” link has visually hidden text, so its accessible name includes the date, for example “Replace secret generated on 21 October 2026 at 8:14am” (2.4.4, 4.1.2).
  6. The environment tag and the “New” tag are text, so neither relies on colour alone. A screen reader reads “New” after the date (1.3.1, 1.4.1).
  7. “Add another secret” is a button in a form, because it changes data. “Replace secret”, “Remove secret” and the back link are links, because they go to another page (4.1.2).
  8. The alert has role="region" and the accessible name “warning: You must copy the credentials”. Its icon is decorative (role="presentation" and focusable="false"), and the warning is given in words, not by the icon or colour alone. Focus is not moved to the alert when the page loads (1.1.1, 1.3.1, 1.4.1, 2.4.3).
  9. The credentials on the copy page are in a dl, with each label in a dt and each value in a dd. The client ID and client secret are text that can be selected (1.3.1).
  10. The Copy button’s accessible name is “Copy credentials client ID and client secret”, which starts with its visible label (2.5.3).
  11. When the credentials are copied, a visually hidden role="status" region with aria-live="polite" announces “Client credentials copied”. Focus stays on the button while its label changes (4.1.3, 3.2.2).
  12. Every link and button can be used with a keyboard, in an order that matches the page. The focus state is the GOV.UK focus style, with the focus colour (#ffdd00) as the background and focus-text (#0b0c0c) as the text (2.1.1, 2.4.3, 2.4.7).
  13. The alert text is black on white, about 19:1. The border and icon are $moj-warning-colour on white, about 3.4:1. The tags are about 9:1 (1.4.3, 1.4.11).
  14. The pages have no horizontal scrolling at 320px wide or at 200% zoom. The client secret and the API URL have no spaces, so they wrap inside the summary list (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE, on each page, with one secret and with two.
  • With only a keyboard, go from the table to the software provider page, then create credentials, add, replace and remove a secret, and copy the credentials each time.
  • Check the client name links, the tags, the secrets table, the alert and the “copied” announcement with a screen reader, such as NVDA or VoiceOver.
  • Check each page at 320px wide and at 200% zoom.
  • Turn off JavaScript. Check that the client name links, adding, replacing and removing a secret, and the back link still work. Check that the Copy button is not shown, Close still works, and the credentials can be selected and copied by hand.

Out of scope

  • A success message after adding, replacing or removing a secret. The “New” tag is the only confirmation for now, so nothing confirms that a secret was removed.
  • Choosing which secret to replace or remove when there are two.
  • More than two secrets for a client.
  • Showing a secret again after it has been created.
  • Changing the name of a client after it has been created.
  • The real API URL for each environment.
  • Anything else on the software provider page, such as the provider’s contact details or history.
  • The Last changed column. See Last changed column.
  • The characters allowed in a client name. See Allowed characters in the client name.
