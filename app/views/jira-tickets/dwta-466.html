User need

As a member of Defra staff who uses the DWT admin portal,
I need to change the client secret a software provider uses,
so that the software provider can keep connecting to the Digital Waste Tracking service without an old or exposed secret.

User story

As a member of Defra staff who uses the DWT admin portal,
I want to add another secret for a client, and to replace or remove a secret,
so that I can give a software provider a new secret and stop the old one working at a time that suits them.

Context

This story covers the Client secret column on the Software providers page and everything you can do with a client secret from there: the Manage client credentials page, adding another secret, and replacing or removing a secret.

There is no research behind this design yet. We are building it so that we can learn from it, and we will test it in user research once it is built.

A client can have two secrets at most. Adding a second one lets the software provider switch to the new secret before the old one stops working. When there are two secrets, the red button removes the older one instead of replacing it, and the most recent one stays.

Replacing and removing secrets are the actions that can break a software provider’s connection, because the secret stops working immediately. Each one asks the user to confirm first.

The service never shows a secret again after it is created, so every secret on the Manage page is redacted. Generated on is at the top of each panel, because it is the one thing that differs when there are two secrets.

Replacing a secret, and adding another, show the new secret on the credentials page built in DWTA-458.

Acceptance criteria

On the Software providers page:

  1. The table has four columns, in this order: Client name, Client ID, Environment, Client secret. The Client secret column cannot be sorted.
  2. In each row, the Client secret cell has a link, “Manage”, followed by the visually hidden text “ client secret for [client name]”.
  3. Given I select “Manage”, then I go to the Manage client credentials page for that client.

On the Manage client credentials page, with one secret:

  1. The page title is “Manage client credentials - DWT admin portal”.
  2. Above the H1 is a caption, “Manage client credentials”. The H1 is the client name.
  3. One panel shows, in this order, each with a bold label above its value: Generated on, External test environment, Client ID and Client secret. External test environment is followed by the API URL. The client secret is “[Redacted for security]”.
  4. Below the panel are a secondary button, “Add another secret”, a warning button, “Replace this secret”, and a link, “Cancel”. “Cancel” goes to the Software providers page.
  5. Given I select “Add another secret”, then a new secret is created straight away, with no confirmation. The existing secret keeps working. I go to the page shown after adding a secret.
  6. Given I select “Replace this secret”, then I go to the replace confirmation page.

On the Manage client credentials page, with two secrets:

  1. There are two panels, with the most recent secret first. Each has the same content in the same order as with one secret, and each client secret is “[Redacted for security]”. Each panel has its own Generated on date and time.
  2. “Add another secret” is not shown. A client never has more than two secrets.
  3. The warning button says “Remove this secret”, not “Replace this secret”.
  4. Given I select “Remove this secret”, then I go to the remove confirmation page.

On the page shown after adding a secret:

  1. The page is the credentials page from DWTA-458, showing the new secret in full, with the warning text and the Copy button. The H1 is “Copy the client credentials”, and the client name is an H2 above the new secret’s panel.
  2. Below the Copy button is a second panel with the existing secret. It has the same content in the same order, with its own Generated on date and time. The client secret is “[Redacted for security]”.
  3. Below the second panel is a primary button, “Close”. Given I select “Close”, then I go to the Software providers page.

On the replace confirmation page:

  1. The page title is “Replace the client secret - DWT admin portal”.
  2. The page is an interruption card and has no other content in the main area. The H1 is “Are you sure you want to replace the current secret?”.
  3. The text is “The current secret for [client name] will stop working immediately. Make sure the software provider knows before you continue.”.
  4. The card has an inverse button, “Yes, replace secret”, and an inverse link, “Go back to Manage client credentials”. The link goes to the Manage client credentials page.
  5. Given I select “Yes, replace secret”, then a new secret is created, the current secret stops working immediately, and I go to the credentials page from DWTA-458 showing the new secret. The client then has one secret.
  6. “Replace this secret” is only offered when the client has one secret.

On the remove confirmation page:

  1. The page title is “Remove the client secret - DWT admin portal”.
  2. The page is an interruption card and has no other content in the main area. The H1 is “Are you sure you want to remove this secret?”.
  3. The text is “The secret for [client name] generated on [date and time of the older secret] will stop working immediately. Make sure the software provider is using the newer secret before you continue.”.
  4. The card has an inverse button, “Yes, remove secret”, and an inverse link, “Go back to Manage client credentials”. The link goes to the Manage client credentials page.
  5. Given I select “Yes, remove secret”, then the older secret is removed and stops working immediately. The most recent secret stays. I go to the Manage client credentials page, which now shows one secret.

On every page in this ticket:

  1. The environment is the one the user is in. In the panels it is capitalised, for example “External test environment”. The API URL is the one for that environment. The design reference shows External test.
  2. The pages match the design references.

Accessibility acceptance criteria

On every page in this ticket, meets WCAG 2.2 AA:

  1. Each page has one H1. On the Manage page the caption above it is a span, not a heading. On the confirmation pages the H1 is the first heading in the card (1.3.1, 2.4.6).
  2. Each “Manage” link has a unique accessible name, “Manage client secret for [client name]”, because of its visually hidden text (2.4.4, 4.1.2).
  3. Table headings are th elements with scope="col". The sortable headings keep the aria-sort values from DWTA-456, and the Client secret heading has none (1.3.1, 4.1.2).
  4. Each panel is an article with an accessible name, “Client credentials generated on [date and time]”, using the date and time in that panel. With two panels, the names are different, so a screen reader user can tell which panel is which. Each panel also starts with Generated on (1.3.1, 2.4.6).
  5. “[Redacted for security]” is real text, not an image or a row of symbols, so a screen reader reads it as it is written (1.1.1, 1.3.1).
  6. “Add another secret” is a button, because it changes data. “Replace this secret” and “Remove this secret” are links that look like buttons, because they go to another page (4.1.2).
  7. The H1 of each confirmation page says the user is being asked to confirm, because a screen reader does not announce the interruption card. “Replace” and “Remove” each ask for confirmation before anything changes (2.4.6, 3.3.4).
  8. On the interruption card, white text on blue is about 5.2:1, the inverse button’s blue text on white is about 5.2:1, and the inverse link is white on blue. The warning buttons are white on red at about 5.1:1 (1.4.3, 1.4.11).
  9. Every link and button can be used with a keyboard, in an order that matches the page. The focus state is the GOV.UK focus style, with the focus colour (#ffdd00) as the background and focus-text (#0b0c0c) as the text (2.1.1, 2.4.3, 2.4.7).
  10. The button groups wrap onto separate lines on small screens, and the pages have no horizontal scrolling at 320px wide or at 200% zoom (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE, on each page.
  • Use the whole journey with only a keyboard, with one secret and with two.
  • Check the panels, the Manage links and both confirmation pages with a screen reader, such as NVDA or VoiceOver.
  • Check each page at 320px wide and at 200% zoom.
  • Turn off JavaScript. Check that adding, replacing and removing a secret still work, and that the table shows, sorted by Client name from A to Z.

Out of scope

  • Creating a new set of credentials. This is in DWTA-458.
  • Choosing which secret to replace or remove when there are two. The red button always acts on the older one.
  • More than two secrets for a client.
  • Changing the name of a client after it has been created.
  • Showing a secret again after it has been created.
  • The Last changed column. See Last changed column.
