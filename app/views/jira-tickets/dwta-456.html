Build the Software providers page and client credentials table

{{ govukButton({ text: "View the design reference page", href: "/jira-tickets/dwta-456/design", classes: "govuk-button--secondary" }) }} {{ govukButton({ text: "View the empty state design", href: "/jira-tickets/dwta-456/design-empty", classes: "govuk-button--secondary" }) }}

User need

As a member of Defra staff who uses the DWT admin portal, I need to see which client credentials software providers have, so that I can manage how they connect to the Digital Waste Tracking service.

User story

As a member of Defra staff who uses the DWT admin portal, I want to see all client credentials for Test and Production in one list, so that I can find the credentials I need to manage.

Context

This story builds the Software providers page and the table on it. The table lists the client credentials for both environments, Test and Production, in one place.

When there are no client credentials, the page shows a short message instead of the table. A table with only headings and sort buttons would not help anyone.

Acceptance criteria

On the Software providers page:

  1. The page title is “Software providers - DWT admin portal”.
  2. The H1 is “Software providers”. Below it is the text “Manage the client credentials that software providers use to connect to the Digital Waste Tracking service.”
  3. The space between the text and the “Client credentials” heading is 50px, or 30px on small screens. This is the same in the empty state. In the design reference, the table’s caption is the heading and the text has a bottom margin of govuk-!-margin-bottom-8. In the empty state, the text has govuk-!-margin-bottom-7 (40px), and the H2 adds 10px of padding above it.
  4. There is one table with the caption “Client credentials”. It lists the credentials for Test and Production together.
  5. The table has four columns, in this order: Client name, Client ID, Environment, Last changed.
  6. There is one row for each set of client credentials.
  7. The Environment column shows “Test” or “Production”.
  8. The Last changed column shows the date and time on two lines, for example “5 October 2026” and, below it, “at 10:15am”. This keeps the times aligned down the column.
  9. The rows are sorted by Last changed, with the newest first.
  10. The Client name, Client ID, Environment and Last changed columns can be sorted.
  11. Given I select a column heading, when the table sorts, then it sorts in ascending order. When I select the same heading again, it sorts in descending order.
  12. The Last changed column sorts by the date and time, not alphabetically.
  13. Given there are no client credentials, then the table is not shown. Instead there is an H2, “Client credentials”, followed by the text “New client credentials will be shown here.”
  14. The page matches the design reference, and the empty state matches the empty state design.

Accessibility acceptance criteria

On the Software providers page, meets WCAG 2.2 AA:

  1. The table has a visible caption, “Client credentials”, which names it for screen reader users (1.3.1).
  2. Every column heading is a th with scope="col" (1.3.1).
  3. Each sortable heading has an aria-sort value (none or descending to start with). The MoJ script turns it into a button and keeps aria-sort up to date (4.1.2).
  4. When the table sorts, a screen reader announces the new order, for example “Sort by Environment (ascending)”, and focus stays on the heading button (4.1.3, 3.2.2).
  5. You can sort every sortable column with a keyboard, and the focus state is visible: the GOV.UK focus style, with a yellow background and black text (2.1.1, 2.4.7).
  6. The sort order is shown by an arrow icon next to the heading, as well as by aria-sort. The icons are hidden from screen readers (1.4.1, 1.1.1).
  7. In the empty state, the H2 “Client credentials” follows the H1, so the headings stay in order (1.3.1, 2.4.6).
  8. The “Software providers” navigation link has aria-current="page" (4.1.2).
  9. The page has no horizontal scrolling at 320px wide or at 200% zoom. If the table is too wide, it can scroll on its own, because it is a data table (1.4.4, 1.4.10). Testers must confirm this.

How to test

  • Run an automated check, such as axe or WAVE.
  • Use the table with only a keyboard, including sorting.
  • Check the table and the sort announcements with a screen reader, such as NVDA or VoiceOver.
  • Check the page at 320px wide and at 200% zoom.
  • Turn off JavaScript and check that the table still shows, sorted newest first.

Out of scope

  • Creating new client credentials.
  • The Client secret column, and rotating a client secret. These will be added in another ticket.
  • The DWT admin portal and Reporting pages. Their navigation links go to # on the design reference page.
  • Showing the total number of records in the table. We haven't discussed this yet.
