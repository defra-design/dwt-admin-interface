User need

As a member of Defra staff who uses the DWT admin portal,
I need to give a software provider the credentials it uses to connect to the Digital Waste Tracking service,
so that its software can connect to the service.

User story

As a member of Defra staff who uses the DWT admin portal,
I want to create client credentials for a software provider and copy them,
so that I can pass them to the software provider.

Context

This story covers the whole journey for creating credentials: the “Create new credentials” button on the Software providers page, a page that asks for the client name, and a page that shows the new credentials.

There is no research behind this design yet. We are building it so that we can learn from it, and we will test it in user research once it is built.

The client name holds both the name of the software provider and the name of the software package, because there is no separate field for each. For example, Waste_Technologies_Software.

The client secret is shown once, on the credentials page. After the user leaves the page it cannot be shown again, so the page warns them to copy it first. The pages work the same in every environment. Only the environment name and the API URL change. The design reference shows External test.

The API URL on the credentials page is an example. We need to confirm the real URL for each environment.

Acceptance criteria

On the Software providers page:

  1. Between the introductory text and the table is a secondary button, “Create new credentials”. The text above it has a bottom margin of govuk-!-margin-bottom-7 (40px on desktop, 25px on small screens), and so does the button.
  2. Given I select “Create new credentials”, then I go to the name page.

On the name page:

  1. The page title is “What is the name of the software provider and package? - DWT admin portal”.
  2. Above the H1 is a caption, “Create external test environment credentials”. The H1 is “What is the name of the software provider and package?”.
  3. There is one text input, labelled “Client name”, with the hint “Enter the name of the software provider and software package, using letters and underscores only. For example, Waste_Technologies_Software.”. The input is two thirds of the width of the content. Autocomplete and spellcheck are off.
  4. Below the input is a primary button, “Generate credentials”, and a link, “Cancel”. “Cancel” goes to the Software providers page.
  5. Given I leave Client name empty and select “Generate credentials”, then the error is “Enter a client name”. See the empty name error design.
  6. Given the client name has anything other than letters and underscores in it, then the error is “Client name must only include letters and underscores”. See the letters and underscores error design.
  7. Given a client with the same name already exists, ignoring capital letters, then the error is “A client with this name already exists. Enter a different client name”. See the duplicate name error design.
  8. Given there is an error, then an error summary titled “There is a problem” is at the top of the page and links to the input. The input shows the same error message and keeps what I typed. The page title starts with “Error: ”.
  9. Given the client name is valid, when I select “Generate credentials”, then the credentials are saved with a new client ID and a new client secret, and I go to the credentials page.

On the credentials page:

  1. The page title is “Copy the client credentials - DWT admin portal”.
  2. Above the H1 is a caption, “Manage client credentials”. The H1 is “Copy the client credentials”.
  3. Under the H1 is warning text: “Copy the client secret before leaving this page. Once you leave this page, you cannot view the client secret again.”.
  4. Under the warning text is an H2 with the client name, with a top margin of govuk-!-margin-top-6 (30px on desktop, 20px on small screens). Below it, one panel shows, in this order, each with a bold label above its value: Generated on, External test environment, Client ID and Client secret. External test environment is followed by the API URL, and the client secret is shown in full.
  5. Generated on is the date and time the secret was created, for example “15 October 2026 at 4:49pm”.
  6. Given JavaScript is on, a secondary “Copy” button is below the panel. When I select it, the generated on date, environment, API URL, client ID and client secret are copied as plain text, in the same order as the panel. Each label is on its own line, followed by its value, with a blank line between each pair.
  7. Given I have copied the credentials, then the message “Client credentials copied” appears beside the button.
  8. Below the panel and the Copy button is a primary button, “Close”, with a top margin of govuk-!-margin-top-6 (30px on desktop, 20px on small screens). There is no back link.
  9. Given I select “Close”, then I go to the Software providers page and the new credentials are in the table.
  10. Given I have left the credentials page and go back to it, then the secret is not shown and I go to the Software providers page.

On every page in this ticket:

  1. The environment is the one the user is in. In the caption it is in lower case, for example “external test”. In the panel it is capitalised, for example “External test environment”. The API URL is the one for that environment. The design reference shows External test.
  2. The pages match the design references.

Accessibility acceptance criteria

On every page in this ticket, meets WCAG 2.2 AA:

  1. Each page has one H1. The caption above it is a span, not a heading. On the credentials page the client name is an H2, so the headings stay in order (1.3.1, 2.4.6).
  2. The name input has a label linked with for and id. The hint and the error message are linked to the input with aria-describedby (1.3.1, 3.3.2, 4.1.2).
  3. The error message starts with the visually hidden text “Error:”, and the input has a red border. The error is not shown by colour alone (3.3.1, 1.4.1).
  4. The error summary is at the top of the page, with focus moved to it when the page loads. Each link in it goes to the input (3.3.1, 2.4.3).
  5. The page title is unique and says what the page is for. On the error page it starts with “Error: ” (2.4.2).
  6. The warning text icon is hidden from screen readers, and the visually hidden text “Warning” comes before the message (1.1.1, 1.3.1).
  7. The panel is an article with an accessible name, “Client credentials generated on [date and time]”, using the date and time in the panel. Each label and value is text that can be selected, not an image (1.3.1).
  8. The Copy button works with a keyboard. Its accessible name is “Copy client ID and client secret”, which includes its visible text (2.1.1, 2.5.3).
  9. The “copied” message is in a role="status" region with aria-live="polite", so a screen reader announces it without focus moving (4.1.3).
  10. Every link and button can be used with a keyboard, in an order that matches the page. The focus state is the GOV.UK focus style, with the focus colour (#ffdd00) as the background and focus-text (#0b0c0c) as the text (2.1.1, 2.4.3, 2.4.7).
  11. The page has no horizontal scrolling at 320px wide or at 200% zoom. The client ID and client secret have no spaces, so testers must confirm they wrap or scroll inside the panel (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE, on each page, including the error state.
  • Use the whole journey with only a keyboard.
  • Check the error summary, the warning text, the panel and the “copied” message with a screen reader, such as NVDA or VoiceOver.
  • Check each page at 320px wide and at 200% zoom.
  • Turn off JavaScript. Check that the journey still works, the Copy button is not shown, and the credentials can be selected and copied by hand.

Out of scope

  • Adding, replacing and removing client secrets, and the Client secret column. These are in DWTA-466.
  • Changing the name of a client after it has been created.
  • The real API URL for each environment.
  • The Last changed column. See Last changed column.
