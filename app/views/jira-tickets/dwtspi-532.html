DWTSPI-532

Sign in to the DWT admin portal with a Defra account

Clickable prototype: Version 9, sign in idea C. Select “Continue to sign in”, pick the account and enter any password to reach the DWT admin portal page. To see the error page, select “Sign in fails” under the password page.

User story

As a member of Defra staff who uses the DWT admin portal,
I want to sign in with my Defra account,
so that I can get into the portal with the account I already use at Defra, and only staff who have been given access can see and change credentials.

Context

This story replaces the current sign in screen, which does not use Microsoft Entra ID, with sign in through Entra ID.

Users who have not signed in see a sign in page. It says what the portal is for and has one button that takes them to the Microsoft sign in pages. After signing in, users land on the DWT admin portal page, which now lists what the portal is for. If sign in fails, users see an error page and can try again.

This story assumes the environment tag in the header from DWTSPI-517 has been built. The tag shows on all 3 pages in this story.

Design acceptance criteria

Header, on the sign in page and the error page

  1. The header shows the Defra logo, “DWT admin portal” and the environment tag, as on the other pages (DWTSPI-517).
  2. There is no navigation bar.
  3. A 10px line in defra-green-dark runs along the bottom of the header, across the full width of the page.

Sign in page (new page)

  1. The H1 is “Sign in to DWT admin portal”, in the large heading size (govuk-heading-l).
  2. Below the H1 is a paragraph, “DWT admin portal allows you to:”, then a bulleted list: “manage software provider credentials” and “search waste organisations”.
  3. Below the list is a primary button, “Continue to sign in”.
  4. The content is in a two-thirds width column.
  5. All spacing is the GOV.UK default for headings, paragraphs, lists and buttons. There are no spacing overrides.

DWT admin portal page

  1. The paragraph under the H1 is replaced with a paragraph, “This site allows the Digital waste tracking service team to:”, then a bulleted list: “manage software provider credentials” and “search waste organisations”.
  2. The environment tag shows in the header, as on the Software provider pages (DWTSPI-517).

Error page (new page)

  1. The H1 is “There was a problem signing you in”, in the large heading size (govuk-heading-l).
  2. Below the H1 is one paragraph: “You have not been signed in. You will need to try again.”
  3. Below the paragraph is a primary button, “Try signing in again”.
  4. The content is in a two-thirds width column.
  5. All spacing is the GOV.UK default for headings, paragraphs and buttons. There are no spacing overrides.
  1. The pages match the design reference.

Acceptance criteria

  1. Given a user has not signed in, when they open any page in the portal, then they see the sign in page.
  2. Given a user is on the sign in page, when they select “Continue to sign in”, then they go to the Microsoft Entra ID sign in.
  3. Given a user signs in with a Defra account that has access, then they land on the DWT admin portal page.
  4. Given a user’s sign in fails, then they see the error page and are not signed in.
  5. Given a user is on the error page, when they select “Try signing in again”, then they go straight to the Microsoft Entra ID sign in, not the sign in page.
  6. Given a user has signed in, then the navigation shows on every page, with “DWT admin portal” as the current page on the DWT admin portal page.
  7. The page titles are “Sign in - External test - DWT admin portal”, “External test - DWT admin portal” and “Error: There was a problem signing you in - External test - DWT admin portal”. In Production, “Production” replaces “External test”.

Accessibility acceptance criteria

Meets WCAG 2.2 AA:

  1. Each page has one banner (header), one main and one contentinfo (footer) landmark. The sign in page and the error page have no navigation landmark. The DWT admin portal page has one, labelled “Menu” (1.3.1).
  2. Each page has one H1, which is the first heading in the main content (1.3.1, 2.4.6).
  3. Each page has a unique title, with the page name, then the environment, then the service name. The error page title starts with “Error: ” (2.4.2).
  4. The lists are marked up as lists (ul and li), not as separate paragraphs (1.3.1).
  5. The button text, “Continue to sign in” or “Try signing in again”, says what the button does (2.4.4, 2.4.6).
  6. The buttons work with a keyboard and have the GOV.UK focus style, with a yellow background and a black bar (2.1.1, 2.4.7).
  7. The environment is shown in the tag text, not by colour alone. The green line is decorative and carries no meaning (1.4.1).
  8. At 320px wide and at 200% zoom, the pages do not scroll sideways, and the logo, service name and tag do not overlap or get cut off (1.4.4, 1.4.10).

How to test

  • Run an automated check, such as axe or WAVE.
  • With only a keyboard, sign in, and go through the error page.
  • Check the pages with a screen reader, such as NVDA or VoiceOver. The page title and the environment in the header are read out, and the lists are read as lists.
  • Check the pages at 320px wide and at 200% zoom.

Questions for refinement

  • Should the error page say why sign in failed (for example, no access or cancelled)? This story has one error page for all causes.
  • Should users go back to the page they first asked for after signing in, rather than always to the DWT admin portal page?

Out of scope

  • The Microsoft sign in pages. They are hosted by Microsoft.
  • Signing out, and showing who is signed in.
  • Giving staff access to the portal.
