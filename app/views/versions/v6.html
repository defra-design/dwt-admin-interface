Design rationale

Design decisions are the same as in version 5, except for the changes recorded in the table above.

There is no user research behind the credentials changes yet. They are built so that we can learn from them, and will be tested in user research. These are the decisions we most want to test:

  • Whether the name page needs the label as the H1, as in the GOV.UK question pages pattern.
  • Whether one message on the “Copy the client credentials” page is enough, or people miss the warning.
  • Whether a limit of two secrets, and removing the older one, is what software providers and staff expect.
  • Whether “[Redacted for security]” is clear to people who expect to see the secret.

This version has its own session data. Credentials created in this version are not shown in version 4.4, and the other way round.
