Design rationale

Apart from the software providers list, design decisions are unchanged from version 3. See the version 3 design rationale for the reasoning behind those pages.

The software providers list is now a table of client credentials. It does not show client secrets, because they should only ever be seen once, when they are created or rotated. The “Rotate” journey will be designed next. The add, detail and API key pages from version 3 are still in version 4, but nothing links to them now.

When credentials are created, the client secret is shown once on a page of its own, with an MoJ information alert to say so. The secret is removed from the session when the user closes the page, so going back to it does not show it again. After a Copy button is pressed, a message names what was copied (“Client ID copied” or “Client secret copied”). It stays on the page and clears only when the other value is copied, so it cannot be missed and never suggests both values are on the clipboard. The Copy buttons only appear when JavaScript is available. Without it, the secret can still be selected and copied by hand.
